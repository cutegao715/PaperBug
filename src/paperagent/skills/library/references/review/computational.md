# Computational, ML and LLM review

Use for actual simulations, computational models, ML, synthetic respondents, LLM agents or agent evaluations. Apply domain resources only where the study makes corresponding physical or behavioral claims.

Trace inputs, initialization, assumptions, update rules, calibration, evaluation, scenarios, outputs and conclusions. Distinguish code execution, verification, empirical validation, prediction and scenario exploration. Inspect baselines, replications, sensitivity, uncertainty and reproducibility according to the contribution. A pattern directly induced by input assumptions needs a bounded interpretation, not an invented emergent mechanism.

For ML, inspect train/validation/test separation, preprocessing boundaries, spatial/temporal/subject leakage, tuning, baselines and distribution shift. Judge transfer-learning language against actual source and target tasks. Request an ablation when a substantive claim depends on distinguishing competing explanations, not as a universal demand.

For LLM work, inspect supplied model identifiers/access dates, prompts, context and conversation state, sampling, run counts, parsers, failures, retries, filtering and aggregation. Unknown seeds, costs or retention conditions remain unknown. Repeated generations from one profile are not independent human participants. Trace attempted, excluded and retained records before evaluating the comparison's population.

Distinguish output consistency, task performance, measurement quality, distributional similarity and human behavioral validity. Generated rationales do not directly demonstrate human mechanisms. For model judges, examine rubric, judge independence, bias, agreement and relevant human adjudication. Keep evaluation claims within the tested workload and setting.

Check the current artifacts and analysis outputs before asserting numerical discrepancies. Running code or passing static tests does not by itself establish the scientific conclusion or general detection quality of an AI reviewer.
