# Prior opinions and cross-round review

Use only when prior comments, versions, responses or review maturity are relevant. Accept an explicitly supplied round label; otherwise describe the purpose as developmental, substantive, integration or submission. Do not infer an R1–R4 sequence from filenames, prose quality or comment counts. These labels are context, not required workflow states.

Keep three layers separate: original instruction, author's claimed action, and change verified in the current manuscript and affected companion files. Reply text or a closed thread does not establish a repair. Conversely, no reply does not mean no repair if the manuscript actually meets the original request.

Use open, partial, resolved, regressed, waived or not_verifiable with a reason and evidence. A missing prior instruction is not proof an issue remains open; use not_verifiable where the comparison cannot be made. Map changed passages by meaning and reader function rather than paragraph numbering alone.

For resolution, locate actual manuscript evidence, check whether it satisfies the request, and inspect affected summaries, displays and supplements. A relocated paragraph can remain unclear; a genuine clarified denominator can resolve the issue. Do not demand wholesale rewriting when a local repair is sufficient.

Preserve historical resolutions but re-evaluate their current applicability when source text, terminology, argument boundaries or venue rules change. A new validity issue remains reportable late in a project. A waiver is an explicit author decision with risk, not a scientific pass.

If the user asks for responses, consult reviewer_response as needed. Only describe changes that are present, distinguishing proposed experiments from completed work. Revision and response artifacts may be requested independently.
