# PaperAgent 科研生命周期与 Workflow 设计 V1

## 一、项目生命周期（Grant Lifecycle）

### G1. 项目申请 Workflow

1. **材料解析**：读取申报通知、指南、模板，提取资格、栏目、字数、格式、截止日期等约束。
2. **选题确认**：询问用户有无意向题目；如没有，结合申报指南、政策热点、用户研究背景推荐 3—5 个题目。
3. **研究设计**：确定核心研究问题、研究目标、内容、方法和创新点，形成整体论证逻辑。
4. **大纲生成**：严格按照申报模板生成栏目与分级提纲，明确各部分写作重点。
5. **逐章节写作**：检索文献与证据，分章节生成，检查目标、内容、方法和成果的一致性。
6. **模拟评审**：从选题价值、创新性、可行性、研究基础、指南契合度等方面评审。
7. **修改交付**：根据评审意见修改，完成正式申请书与必要附件。

用户确认点：选题、研究设计、大纲、最终正文及重要评审修改。

交付物：申请书、论证活页、参考文献、评审报告、待补事实清单。

### G2. 中期进展 Workflow

1. 读取立项申请书、任务书及中期报告模板。
2. 提取原定研究目标、研究任务、进度节点与预期成果。
3. 收集用户实际进度、阶段成果、调研及实验材料。
4. 对照原计划分析：已完成、进行中、延期、发生调整。
5. 根据模板生成大纲，并逐章节撰写中期报告。
6. 检查实际进展与原申请书的对应关系。
7. 评审与修正，给出后续工作建议。

用户确认点：实际进展、计划调整、阶段成果、最终报告。

交付物：中期报告、任务完成度对照表、后续研究计划、风险提示。

### G3. 项目结题 Workflow

1. 读取申请书、任务书、中期报告及结题要求。
2. 提取研究目标、考核指标、成果承诺。
3. 收集实际成果及其证明材料。
4. 建立**承诺成果—实际成果—证明材料**对应关系。
5. 识别未完成、发生变更或缺少证明的事项。
6. 按结题模板生成报告大纲、逐章节撰写。
7. 模拟结题评审，修正报告并整理附件。

用户确认点：实际成果、未完成事项及说明、结题材料。

交付物：结题报告、成果清单、证明材料目录、结题风险报告。

**特殊规则**：不能为了满足结题要求而将未完成成果描述为已完成。

## 二、期刊 / 会议论文生命周期（Publication Lifecycle）

### P1. 论文编写 Workflow

1. **选题发现**：优先询问用户是否已有题目；否则结合历史课题、已有论文、研究热点推荐。
2. **研究问题设计**：提出具体研究问题，分析研究价值、已有研究缺口、可验证性与预期贡献。调用专项 Research Question Skill。
3. **研究设计**：确定理论框架、研究方法、数据需求、实验或实证方案。
4. **深度文献调研**：系统检索国内外研究，建立文献证据库，识别关键研究脉络与不足。
5. **论文大纲**：按学科、研究类型及目标期刊要求生成结构。
6. **逐章节写作**：完成引言、相关研究、方法、实验/实证、结果、讨论与结论等适用章节。
7. **质量评审**：评价创新性、论证逻辑、方法合理性、证据充分性、投稿竞争力。
8. **修改迭代**：根据评审意见修改，输出投稿候选稿。

用户确认点：选题、研究问题、研究方案、大纲、重大修改。

交付物：论文正文、参考文献、研究问题说明、方法与数据说明、质量评审报告。

特殊机制：
- 不同学科动态加载专用 Skill，不能强制使用同一种论文结构。
- 已完成的实验结果和计划中的实验必须区分。
- 缺乏真实数据时，只能完成研究设计或结果章节框架，不得生成虚构结果。

### P2. 投稿机会与期刊匹配 Workflow

1. 读取论文或研究构想，分析研究主题、创新性、成熟度与质量。
2. 检索候选期刊、会议、专题征稿（Special Issue / CFP）。
3. 综合评价研究方向匹配度、学术层次、审稿周期、发表费用、截止日期、录用难度等。
4. 推荐 3—5 个投稿目标，按适配度排序，说明优缺点和风险。
5. 用户选择投稿目标。
6. 读取投稿指南、模板及作者须知。
7. 完成格式适配、语言修改、字数控制、引用格式、Cover Letter 等材料准备。
8. 检查投稿完整性。

用户确认点：目标期刊/会议、投稿版本。

交付物：投稿推荐报告、目标期刊适配稿、Cover Letter、投稿检查清单。

**重要设计**：投稿目标可以在论文写作前、中、后确定，不应强制等论文写完才开始推荐。

### P3. 投稿与追踪 Workflow

1. 用户提供投稿信息，或授权连接邮箱。
2. 建立 Submission 记录：期刊、稿件编号、投稿日期、当前状态。
3. 监测投稿相关邮件，并在有可靠来源时更新状态。
4. 识别编辑决定、审稿意见、修改要求及截止日期。
5. 对审稿意见进行分类，生成修改策略与逐条回复草稿。
6. 用户确认修改内容，完成论文修改和 Response Letter。
7. 追踪重新提交及后续审稿进展。
8. 根据录用、拒稿、撤稿等结果进入不同分支。

典型状态：

Submitted → With Editor → Under Review → Revision → Accepted

其他分支：Rejected → 重新选刊；Revision → 再审；Withdrawn → 结束。

用户确认点：审稿修改方案、回复信、重新投稿及任何对外提交操作。

交付物：投稿状态记录、审稿意见分析、修改稿、回复信、录用记录。

以论文录用为主要完成节点，见刊和出版跟踪可继续作为后续服务。

## 三、毕业论文生命周期（Thesis Lifecycle）

### T1. 论文开题 Workflow

1. 识别学历层次、学科、学校规范及导师要求。
2. 读取用户已有论文、课题、研究积累。
3. 询问是否已有毕业论文题目。
4. 无题目时，结合研究积累、学术前沿与完成条件推荐选题。
5. 深入论证研究问题、研究价值、可行性与创新性。
6. 检索文献，形成国内外研究综述。
7. 确定研究目标、内容、方法、技术路线及计划。
8. 按学校模板生成开题报告。
9. 模拟开题评审，修改完善。

用户确认点：选题、核心研究问题、研究方案、开题报告。

交付物：开题报告、文献综述、技术路线、研究计划、开题答辩材料。

### T2. 毕业论文中期 Workflow

1. 读取开题报告、研究计划和中期检查要求。
2. 提取原定目标、研究任务与阶段节点。
3. 收集已完成的研究工作、数据、实验与论文草稿。
4. 对照开题计划评估实际进展。
5. 识别研究偏差、困难及是否需要调整研究方案。
6. 生成中期检查报告。
7. 评审并规划后续研究任务。

用户确认点：实际进度、重大研究调整、最终中期报告。

交付物：中期检查报告、进度分析、后续任务计划。

### T3. 毕业论文终稿编写 Workflow

1. 读取开题报告、中期报告、导师意见、已发表论文及现有草稿。
2. 依据学校规范建立毕业论文整体结构。
3. 梳理贯穿全文的核心研究问题和逻辑主线。
4. 确定章节安排、研究材料及证据需求。
5. 按章节完成正文写作、引用和图表整理。
6. 检查章节之间的逻辑递进、术语、研究问题、方法及结论的一致性。
7. 检查研究贡献是否充分，结论是否得到证据支持。
8. 根据导师反馈进行结构性或局部修改。
9. 完成格式检查和提交前评审。

用户确认点：整体框架、研究贡献、重大章节调整、最终版本。

交付物：毕业论文终稿、参考文献、图表目录、格式检查报告、待修改问题清单。

特殊机制：
- 应充分复用已有研究成果，但必须处理引用、版权及学术规范要求。
- 学位论文比期刊论文更重视研究体系完整性、章节关联和整体贡献。
- 不同学历层次应启用不同深度的研究设计与评审标准。

### T4. 盲审与答辩 Workflow

1. 读取学校盲审、答辩及学位授予要求。
2. 对论文进行模拟专家评审。
3. 检查匿名化、引用、格式和提交材料完整性。
4. 接收真实盲审意见，分类制定修改方案。
5. 根据意见修改论文，生成修改说明。
6. 制作答辩 PPT、讲稿，设计可能的专家提问。
7. 模拟答辩，优化研究贡献表达和关键问题回答。
8. 整理正式答辩意见，修改最终归档版本。
9. 确认论文提交和相关流程状态。

用户确认点：盲审修改方案、答辩材料、最终归档版本。

交付物：盲审修改稿、修改说明、答辩 PPT、答辩问答材料、最终归档论文。

## 四、跨生命周期的主动科研服务

这一部分不应定义为某个生命周期内部的固定步骤，而应由 Proactive Runtime 持续执行。

### A1. Research Radar

持续关注用户研究方向及各科研项目：
- 新发表的高相关文献
- 新出现的研究热点与研究缺口
- 适合开展的论文选题
- 值得关注的新方法、数据集和研究成果

触发：定期检索、重要文献更新、用户研究兴趣变化。

输出：科研简报、选题建议、文献推荐。

### A2. Opportunity Radar

持续关注：
- 基金、课题及教改项目申报机会
- 期刊专题征稿
- 学术会议 CFP
- 项目和投稿截止日期

触发：新机会出现、截止日期临近、用户条件或研究方向变化。

输出：机会推荐、适配度分析、行动建议。

### A3. Progress & Feedback Watcher

持续跟踪：
- 项目中期、结题节点
- 论文投稿状态
- 导师与审稿人反馈
- 毕业论文阶段性任务

触发：邮件事件、截止日期、任务状态变化。

输出：进度提醒、反馈摘要、下一步建议。

## 五、所有 Workflow 共用的运行规则

### 1. Workflow 不等于固定流水线

- Agent 判断当前阶段，可跳过已经完成的工作。
- 支持从任意阶段进入、暂停、恢复和回退。
- 不强制用户按顺序执行全部 Workflow。
- 每个 Workflow 有明确的输入、输出、完成条件和状态。
- 已批准的研究设计或大纲发生重大变化时，应重新确认。

### 2. 用户确认策略

**必须确认**：
- 核心选题与研究问题
- 重大研究方案调整
- 真实事实和研究数据
- 最终正式交付版本
- 投稿、邮件发送等对外操作

**建议确认**：
- 大纲
- 创新点
- 评审修改方案

**无需逐次确认**：
- 文献检索
- 常规资料整理
- 引用格式修正
- 非实质性语言润色
- 自动质量检查

初次进入选题任务时，优先自然地询问“是否已有意向题目”，而不是直接要求填写大量信息。

### 3. 质量检查机制

ERROR：虚构事实、错误引用、违反官方强制规则、关键材料缺失。

WARNING：内容不完整、论证不足、研究设计不一致、缺少必要证据。

SUGGESTION：题目优化、论证深化、创新表达、语言和结构优化。

### 4. 跨生命周期成果复用

同一个研究课题可以同时关联：
- 一个基金项目
- 多篇期刊论文
- 一篇毕业论文
- 多个研究成果

已确认的研究问题、文献、数据、方法和成果可以复用，但各个 Workflow 的文档版本、审核状态和交付要求必须独立管理。
