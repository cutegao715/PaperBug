# PaperAgent 云端后台和可安装本地工作空间拆分设计

## 目标与范围

把现有第一阶段原型整理成两个可以独立安装、启动和发布的工程：云端后台和用户本地工作空间。用户注册登录后，可以创建自己的研究空间、向云端模型发送对话并查看历史；不同账号的数据隔离。本地客户端通过云端 FastAPI 的 HTTP 接口通信。

保留现有功能和数据；旧研究空间及其 API 暂时保持兼容。首轮不声称具备生产级安全、云端部署或完整本地文件操作，不迁移全部旧科研能力，不安装到用户电脑或部署云端。

## 实现方式选择

1. **两个独立工程目录，留在同一仓库**：各自拥有依赖、源码、测试、配置和启动入口，以 HTTP/JSON 通信；旧工程暂保留。优点是能独立构建部署，且可渐进迁移；接口需要版本管理。
2. 同一 Python 包内按模块分层：迁移快，但本地发行物容易继续携带云端模型代码与密钥配置，无法清晰控制独立依赖。
3. 直接拆成两个仓库：权限与发布更独立，但当前没有必要的仓库及发布流程，会增加迁移和协调成本。

按用户提出的两个文件结构，选择方案 1；不设第三个独立 shared 工程，公开接口由云端 OpenAPI 和契约测试维护。

## 目录与职责

```text
backend/                     云端后台独立工程
  pyproject.toml             后台依赖、构建与启动入口
  src/paperagent_cloud/      FastAPI、用户身份、研究空间、对话、模型访问
  tests/                     后台隔离、并发和对话测试
  .env.example               云端配置示例，不含密钥
frontend/                    可安装本地客户端独立工程
  pyproject.toml             本地依赖、构建与启动入口
  src/paperagent_desktop/    本机 FastAPI、静态界面与本地能力
  tests/                     本地启动、资源与接口测试
  README.md                  安装、运行与配置
src/paperagent/              旧工程，过渡期保持原路径和入口
docs/                        整体设计和迁移说明
```

桌面工程封装现有 HTML/CSS/JS，并由本机 FastAPI 只绑定回环地址提供界面。前端通过 HTTPS（本机开发可用 HTTP 回环）访问云端 FastAPI；本机 FastAPI 后续提供受控本机操作接口。首轮以独立 Python 包和命令行入口证明可安装，不把这等同于完成 Windows 安装程序或桌面容器；后续可封装成安装包。

云端后台迁出已有 `src/paperagent/cloud/` 原型，并消除对旧工程 `paperagent.env`、`paperagent.harness.llm` 的运行时依赖：在后台工程内迁移必要模型客户端及配置加载能力，保留协议行为与供应商配置。后台不能加载桌面程序或访问用户本机路径。现有用户数据库的路径和数据结构保持兼容，切换启动入口前明确数据文件位置。

本地客户端不安装云端模型 SDK、账号数据库或云端方法 Skill。模型凭据只在后台设置，客户端仅保留用户会话凭据；本地文件选择在首轮保持当前只显示名称的行为。静态文件随本地包发布，不能依赖仓库根目录才能运行。

## 接口与数据

沿用现有 `/api/auth/register`、`/api/auth/login`、`/api/auth/logout`、`/api/spaces` 和 `/api/spaces/{id}/messages` 及其 JSON 语义，服务端继续从令牌确定用户。后台为本地客户端来源配置明确 CORS；远程访问使用 HTTPS。本机 API 只供本机页面使用，不向局域网暴露。

本次不自动上传本地文件或旧对话。账户、研究空间与对话保留在原云端数据库；登录令牌语义和过期时间沿用原型。由于原型使用单实例 SQLite 和同步调用，多实例、生产安全及可靠队列仍属于后续工作。

## 迁移与验证

1. 记录并运行当前用户隔离和幂等测试，保证现状可比较；保留现有数据库和旧工程。
2. 建立后台独立工程，迁移云端服务与其必要依赖；以独立安装环境验证启动和现有 API 兼容，不从根目录隐式导入旧包。
3. 建立本地独立工程，打包静态资源及回环 FastAPI 启动入口；从仓库以外目录启动并访问界面。
4. 使用两个用户验证注册、登录、空间创建、会话隔离、重复请求以及失败重试；验证前后端各自可安装，云端模型调用以模拟供应商验证，真实调用仅在用户已有配置和授权下进行。
5. 更新启动文档、配置样例与旧入口迁移说明；运行相关回归测试，记录未完成的文件操作、生产安全及打包工作。

迁移采用复制并校验后切换的方式，避免覆盖旧代码和现有数据；原型路径是否保留兼容导入由测试覆盖，不能保留两个可分别演化的有效实现。由于当前目录不是 Git 仓库，不执行提交或基于 Git 的工作树操作。
