# 云端 Agent 与本地执行闭环实施计划

**Goal:** 将现有 Agent 的多步动作接入云端，并通过本机受控执行与回传完成科研任务。

**Architecture:** 两个独立工程；云端保存用户隔离的任务、步骤和操作，本机只处理经明确授权的结构化文件操作，结果由云端继续用于推理。

**Tech Stack:** Python、FastAPI、SQLite、现有 Agent 动作协议与本地 PDF 工具。

**Spec:** `docs/personal_research_assistant_cloud_local_transformation_plan_v1.md` 第 4 至 6 节。

## 工作顺序

1. 建立持久化、用户隔离的任务及本机操作协议，覆盖重复请求、越权和恢复。
2. 将原 Agent 决策协议与云端可执行能力分离，实现多步运行、检查点和失败恢复；本机动作转成受限操作。
3. 本地实现用户选定文件的授权、读取及安全回传；禁止任意路径与未经授权的写入。
4. 界面支持发起任务、展示执行状态、授权材料发送、查看结果和恢复。
5. 两端独立安装后，使用实际 HTTP 和模拟模型验证完整流程、跨账号隔离、断网恢复和重复回传，再运行回归测试。

## 验收重点

- 本地路径不发送云端；用户选择的文件内容仅在明确授权后发送。
- 任务状态与操作领取、结果持久化；不同用户不能访问彼此的任务和操作。
- 任意失败不得假称任务成功；重复请求和回传不产生重复副作用。
- Agent 使用原有科研动作协议，受支持动作和尚未迁移能力明确展示。
- 原始文件不被隐式覆盖；任务与执行进度能够在重启后恢复或明确提示。
