## 总体判断

当前工程已经不是纯静态原型：项目、文件导入、Agent Run、运行流式事件、文献/证据/草稿保存、任务/通知/Radar 的部分领域接口都存在。但前端暴露了一个接近完整产品的界面，其中不少入口仍是占位逻辑或“半接入”，导致用户预期高于真实能力。

下一阶段目标不是继续铺新模块，而是把核心闭环打稳：创建项目 -> 导入材料 -> 项目对话 -> Agent 调工具 -> 保存结果 -> 下次打开还能接着用。

## 建议的迭代顺序

1. 稳住 P0：项目对话持久化、最近消息进入 Agent 上下文、导入失败可解释。
2. 打磨材料导入：DOC/WPS 转换、本地材料状态、材料详情。
3. 让科研房间变成唯一可靠入口：导入、对话、草稿、证据都先在这里完成。
4. 再恢复 Radar / 机会 / 信箱的存在感，用真实数据替代静态主题和占位按钮。

- 工具调用记录：`tool_calls.jsonl` 记录每次工具调用的 `call_id`、`parent_run_id`、输入摘要、状态、错误、延迟和来源。
- 运行状态：`run_state.json` 记录当前 run 的状态、阶段、迭代、当前 action、最后错误、恢复建议、最终 trace 路径。
- 文件权限：`permissions.json` 记录项目授权目录和写入目录；导入文件/文件夹会自动把对应目录加入项目授权 root。
- Agent 上下文：observation 中加入 `filesystem.allowed_roots` 和 `recent_tool_calls`，让模型知道当前能访问哪些本地目录，以及刚才工具是否失败。
- 错误恢复：JSON/action 解析失败、文件权限、错误路径、超时都会生成结构化 recovery 建议，并写入 run state 和最终摘要。

下一步建议：

1. 前端把 `runtime`、`tool_calls`、`permissions` 渲染成“执行链路/权限/诊断”面板。
2. 把 `import_file` / `import_folder` 也完全收敛到统一 ToolExecutor 分发，减少旁路逻辑。
3. 增加真正的 step resume：失败后从最后一个可恢复 step 继续，而不是重新开一轮完整 run。

## 任务打法升级

更新日期：2026-10-06

已将课题申报 workflow 从“知识规则”升级为“任务打法”：

- `grant_application_playbook`：识别任务阶段（选题、题目优化、论证活页、完整申请书、修改润色、评审检查、导出交付），并给出阶段动作、写作原则和交付前检查。
- `deliverable_contracts`：定义不同阶段的交付物，如选题的候选题/排序/风险/指南匹配，活页的栏目，完整申请书的待填项/论证/基础/经费建议等。
- `quality_review_levels`：分为 ERROR、WARNING、SUGGESTION，避免把所有问题都做成硬阻断。
- `interaction_policy`：能先做就先做，不为非必要信息阻塞用户；正式成稿前再问姓名、单位、团队、成果、数据、合作单位、经费等事实信息。
- `application_completeness` 已调整：字数不足、题目过泛、创新点过度、方法机械等更多作为 warning/suggestion；必填栏目缺失、坏引用等才继续阻断。

本轮继续打磨课题申请 workflow：

- 增加阶段识别：`topic_selection`、`title_optimization`、`argument_sheet`、`full_application`、`revision`、`review_check`、`export_delivery`。
- `next_actions` 现在按阶段变化：选题先产候选题，题目优化先诊断原题，活页关注匿名风险，申请书分栏扩写，评审检查先诊断再局部修改，导出前汇总风险。
- `finish` 阶段会把 workflow 阶段、待确认信息和质量提示追加到用户可见 summary，避免“完成了”但用户不知道风险。
- 对完整申请书/论证活页增加篇幅 guard：如果 `finish` 时仍触发 too-short warning，会返回 `draft_expansion_required`，要求继续 `append_draft` 分栏扩写，避免短提纲被当成最终交付。
- 写作流水线进一步明确为：选题 → 大纲 → 每个章节写核心内容 → 扩写扩充 → 润色 → 图/公式/表格建议 → 质量检查与导出。workflow 现在可识别 `outline`、`section_seed`、`expansion`、`polishing`、`visual_formula` 等阶段，避免从选题直接跳到最终申请书。
